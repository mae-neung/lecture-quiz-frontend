# UI 수동 점검표

UI 또는 사용자 흐름을 변경한 PR의 PR Gate에서 실행한다. 모든 UI 변경에 전체 라우트 점검을 요구하지 않고 변경 영향에 따라 `scoped` 또는 `full`을 선택한다. 작업 중 `targeted` 검증이 필요하면 해당 항목만 먼저 점검할 수 있다. 새 테스트 라이브러리는 필요하지 않다.

- `scoped`: 한 화면의 텍스트·스타일·컴포넌트·상호작용처럼 영향 범위가 제한된 변경
- `full`: 라우터, 전역 레이아웃, 내비게이션, 공용 UI 기반, 디자인 토큰, 여러 화면의 사용자 흐름 변경

## 준비

1. Node.js 24.15.0 이상에서 `pnpm dev --host 127.0.0.1`을 실행한다.
2. 브라우저, OS, 검사한 데스크톱·모바일 뷰포트 크기를 기록한다.
3. 개발자 콘솔의 오류 유무를 확인한다.

## 범위 점검

모든 UI 변경에서 영향받은 화면과 동작만 확인한다.

| 점검 | 기대 결과 |
| --- | --- |
| 변경한 화면과 직접 연결된 이동 경로 | 주요 콘텐츠와 이동이 계획대로 동작한다. |
| 핵심 사용자 과업의 시작부터 완료까지 | 막다른 화면이나 불필요한 반복 없이 완료할 수 있고 취소·뒤로 가기가 예측 가능하다. |
| 주요·보조 행동과 UX 문구 | 우선순위와 결과를 이해할 수 있으며 오해를 유도하거나 강제하는 표현이 없다. |
| 비동기 행동의 진행과 완료 | 처리 중임을 알 수 있고 중복 실행이 방지되며 성공·실패 결과가 명확하다. |
| 입력 검증과 실패 복구 | 오류 위치와 해결 방법이 명확하고 입력이 가능한 한 유지되며 재시도할 수 있다. |
| 파괴적이거나 되돌리기 어려운 행동 | 해당 시 결과를 사전에 알리고 확인·취소 또는 되돌리기 수단을 제공한다. |
| 라이트·다크 모드(새 시각 디자인·foundation 변경 시) | 동일한 semantic token과 UI 상태가 1:1로 표현되고 콘텐츠·아이콘·경계가 두 모드에서 모두 구분된다. |
| 타이포그래피(새 시각 디자인·foundation 변경 시) | 승인된 font·fallback·위계·굵기·행간이 적용되고 모바일·데스크톱에서 잘림이나 겹침이 없다. |
| 영향받는 데스크톱·모바일 폭 | 콘텐츠가 잘리지 않고 불필요한 가로 스크롤이 없다. |
| 변경한 링크·버튼의 키보드 조작 | `Tab`·`Enter`로 접근할 수 있고 포커스가 보인다. |
| 변경 기능의 성공·빈 상태·오류 상태 | 정의된 상태가 동작한다. 해당 상태가 없으면 생략한다. |
| 개발자 콘솔 | 변경 동작 중 새 오류가 발생하지 않는다. |

## 전체 회귀 점검

`full` 수준일 때 범위 점검에 더해 다음 기준 라우트를 확인한다.

| 점검 | 기대 결과 |
| --- | --- |
| `/` 열기 | 홈 제목과 주요 링크가 표시된다. |
| `About` 링크 또는 `/about` 열기 | About 화면이 표시되고 홈으로 돌아갈 수 있다. |
| 존재하지 않는 경로 열기 | 404 안내가 표시되고 홈 링크로 복귀할 수 있다. |
| 모바일 폭(예: 375px)에서 기준 화면 확인 | 공용 레이아웃과 내비게이션이 잘리지 않는다. |
| 키보드 `Tab`·`Enter`로 기준 탐색 | 전역 링크·버튼에 접근할 수 있고 포커스가 보인다. |

## 결과 기록

Handoff의 검증 근거에 선택한 수준(`scoped` 또는 `full`), 각 점검의 `pass`·`fail`·`not-run`, 브라우저·뷰포트, 실패 재현 단계와 미실행 이유를 적는다. 화면이나 사용자 흐름을 바꾸지 않은 작업은 UI 점검 항목 자체를 생략한다. 수동 점검은 단위 테스트·타입 검사·빌드를 대체하지 않는다.

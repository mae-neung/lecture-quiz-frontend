# Orchestration Gates

Gate는 다음 역할로 넘어가기 전에 현재 결과가 준비됐는지 확인하는 체크포인트다.

## 1. Intake Gate

작업 시작 전 확인한다.

- 목표가 한 문장으로 설명되는가?
- 변경 대상과 제외 범위가 구분됐는가?
- 관련 저장소와 파일에 접근할 수 있는가?
- 완료 조건이 있는가?

불명확한 내용이 결과를 크게 바꾼다면 사용자에게 질문한다. 합리적인 기본값으로 진행할 수 있다면 가정을 명시한다.

## 2. Plan Gate

Planner 결과를 확인한다.

- 수정할 기능과 파일 후보가 구체적인가?
- 데이터·상태·사용자 흐름이 설명됐는가?
- 위험과 미확정 사항이 표시됐는가?
- 검증 방법이 정의됐는가?
- 사용자가 계획 승인을 요청했다면 승인을 받았는가?

통과하지 못하면 구현을 시작하지 않는다.

## 3. Design Gate

UI 작업이 있을 때만 확인한다.

- 각 화면의 목적과 주요 동작이 명확한가?
- 로딩·빈 상태·오류 상태가 고려됐는가?
- 키보드와 접근성 요구가 고려됐는가?
- 모바일과 데스크톱 우선순위가 설명됐는가?
- 기존 디자인과 컴포넌트를 재사용하는가?

## 4. Implementation Gate

Frontend Agent가 자체 확인한다.

- 계획 범위 안에서만 변경했는가?
- 기존 폴더 책임과 코드 스타일을 유지했는가?
- 비밀 값이나 임시 디버깅 코드를 남기지 않았는가?
- 오류와 빈 상태를 필요한 만큼 처리했는가?

## 5. Verification Gate

코드 변경 후 확인한다.

```bash
pnpm lint
pnpm build
```

테스트가 있으면 관련 테스트도 실행한다. 실패한 명령이 있으면 Review Gate로 넘어가지 않는다. 재시도는 `AGENTS.md`의 최대 2회 규칙을 따른다.

## 6. Review Gate

Reviewer가 다음 우선순위로 검사한다.

1. 기능 오류와 요구사항 누락
2. 상태 전이와 데이터 손실 위험
3. 보안과 비밀 정보 노출
4. 접근성과 반응형 동작
5. 유지보수성과 중복

수정이 필요한 문제에는 파일, 위치, 영향, 권장 수정 방향을 포함한다. 중대한 문제가 없을 때만 통과시킨다.

## 7. Completion Gate

Coordinator가 최종 확인한다.

- 사용자의 요청이 충족됐는가?
- 검증 결과가 기록됐는가?
- Reviewer의 차단 문제가 해결됐는가?
- 남은 제한 사항이 사용자에게 전달됐는가?

통과하면 변경 요약과 검증 결과를 보고한다.

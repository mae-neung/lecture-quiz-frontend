# Orchestration Gates

Gate는 다음 역할로 넘어가기 전에 현재 결과가 준비됐는지 확인하는 체크포인트다.

## 1. Intake Gate

작업 시작 전 확인한다.

- 목표가 한 문장으로 설명되는가?
- 변경 대상과 제외 범위가 구분됐는가?
- 관련 저장소와 파일에 접근할 수 있는가?
- 완료 조건이 있는가?

불명확한 내용이 결과를 크게 바꾼다면 사용자에게 질문한다. 합리적인 기본값으로 진행할 수 있다면 가정을 명시한다.

## 2. Plan Gate

Planner 결과를 확인한다.

`AGENTS.md`의 경량 경로에서는 Coordinator가 목표·응집된 변경 범위·검증 방법과 생략 근거를 짧게 기록한 뒤 이 Gate를 판정한다. 파일 수만으로 표준 경로로 전환하지 않으며, 작업 중 위험이나 책임 범위가 커지면 전환한다.

- 수정할 기능과 파일 후보가 구체적인가?
- 데이터·상태·사용자 흐름이 설명됐는가?
- 위험과 미확정 사항이 표시됐는가?
- 검증 방법이 정의됐는가?
- 사용자가 계획 승인을 요청했다면 승인을 받았는가?

통과하지 못하면 구현을 시작하지 않는다.

## 3. Design Gate

새로운 화면 구조·사용자 흐름·복합 상태 설계가 있을 때만 확인한다. 기존 패턴을 따르는 텍스트·스타일·컴포넌트 수정은 별도 Design Gate 없이 구현할 수 있다.

- 각 화면의 목적과 주요 동작이 명확한가?
- 로딩·빈 상태·오류 상태가 고려됐는가?
- 키보드와 접근성 요구가 고려됐는가?
- 모바일과 데스크톱 우선순위가 설명됐는가?
- 기존 디자인과 컴포넌트를 재사용하는가?

## 4. Implementation Gate

Frontend Agent가 자체 확인한다.

- 계획 범위 안에서만 변경했는가?
- 기존 폴더 책임과 코드 스타일을 유지했는가?
- 비밀 값이나 임시 디버깅 코드를 남기지 않았는가?
- 오류와 빈 상태를 필요한 만큼 처리했는가?

## 5. Verification Gate

코드 변경 후 위험과 영향 범위에 맞는 검증 수준을 선택한다.

- `none`: 문서·주석처럼 애플리케이션 실행에 영향을 주지 않는 변경
- `targeted`: 명확하고 되돌리기 쉬운 작은 변경에 대한 관련 lint, 테스트, 타입 검사 또는 수동 점검
- `full-pr`: PR 생성·업로드 또는 최종 반영 전 최종 변경본에 대한 전체 검증

의존성, 공용 API, 상태 로직, 라우팅, 빌드 설정, 보안·배포에 영향이 있거나 영향 범위가 불명확하면 검증 범위를 넓힌다. 선택한 검증 수준과 근거, 명령별 결과, 생략한 항목의 이유를 Handoff에 기록한다. 선택한 검증이 실패하면 Review Gate로 넘어가지 않는다.

## 6. Review Gate

변경 위험에 따라 일반 변경은 `reviewer`, 인증·보안·데이터 손실·공용 API·광범위 리팩터링·배포 변경은 `reviewer_high`가 다음 우선순위로 검사한다.

검토를 시작할 때 Handoff의 브랜치·HEAD·작업 트리와 실제 변경본이 일치하는지 확인한다. 다르면 이전 검증 결과를 그대로 통과 근거로 사용하지 않는다.

1. 기능 오류와 요구사항 누락
2. 상태 전이와 데이터 손실 위험
3. 보안과 비밀 정보 노출
4. 접근성과 반응형 동작
5. 유지보수성과 중복

수정이 필요한 문제에는 파일, 위치, 영향, 권장 수정 방향을 포함한다. 중대한 문제가 없을 때만 통과시킨다.

## 7. PR Gate

사용자가 PR 생성·업로드 또는 최종 반영을 요청하면 리뷰 반영이 끝난 마지막 코드 변경 후 다음 명령을 실행한다.

```bash
pnpm verify
```

`pnpm verify`는 lint, test, 타입 검사를 포함한 build를 순서대로 실행한다. 별도 `pnpm typecheck`는 build와 TypeScript 검사가 중복되므로 PR Gate에서 실행하지 않는다. 관련 테스트를 추가하거나 갱신하며, 실패하면 PR을 생성하지 않는다. 재시도는 `AGENTS.md`의 최대 2회 규칙을 따른다.
UI·사용자 흐름 변경 시에는 [UI 수동 점검표](ui-smoke-checklist.md)에서 변경 범위에 맞는 수준을 실행하고 브라우저·화면 크기·결과를 Handoff에 남긴다. 전체 검증 후 코드가 다시 변경되면 기존 `full-pr` 결과는 무효이며, 최종 변경본으로 이 Gate를 다시 수행한다. 실행하지 못한 항목이 있으면 성공으로 보고하거나 PR을 생성하지 않고 이유와 필요한 결정을 기록한다.
승인·권한·외부 상태가 필요한 명령은 반복 대기하지 않고 `needs-decision` Handoff로 Coordinator에게 반환한다.

## 8. Completion Gate

Coordinator가 최종 확인한다.

- 사용자의 요청이 충족됐는가?
- 검증 수준과 결과, 생략한 항목의 이유가 기록됐는가?
- PR 요청이 있다면 최종 변경본으로 PR Gate를 통과했는가?
- Reviewer의 차단 문제가 해결됐는가?
- `needs-decision`으로 남은 승인·외부 조치가 해결됐는가?
- 남은 제한 사항이 사용자에게 전달됐는가?

통과하면 변경 요약과 검증 결과를 보고한다.

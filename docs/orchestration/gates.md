# Frontend Gates

공통 Plan, Review, Completion Gate와 검증 수준은 전역 `AGENTS.md`를 따른다. 아래 항목만 프론트엔드 작업에 추가한다.

## Design Gate

새 화면 구조·사용자 흐름·복합 상태 또는 불명확한 시각 방향이 있을 때 적용한다. 새로운 디자인 방향은 전역 Designer 승인 절차를 먼저 통과해야 한다.

### 1. Direction Preview Gate

- 핵심 과업과 시각적 성격을 가장 잘 보여주는 대표 페이지 하나를 선정했는가?
- 동일한 콘텐츠·정보·핵심 흐름으로 대표 페이지의 서로 다른 3가지 시안 또는 프리뷰만 만들었는가?
- 각 안이 번호, 핵심 콘셉트, 레이아웃·대표 UI 패턴, UX 장단점, 임시 컬러·타이포그래피 방향과 추천안을 포함하는가?
- 비교 단계에서 정식 팔레트·token을 확정하거나 대표 페이지 외의 페이지를 작업하지 않았는가?
- 사용자가 3안 중 하나를 선택했는가?

방향이 선택되기 전에는 Design Foundation Gate로 넘어가지 않는다.

### 2. Design Foundation Gate

선택된 한 방향에 대해서만 다음을 확인한다.

- 화면 목적과 주요 동작이 명확한가?
- 대상 사용자, 사용 맥락, 핵심 과업과 성공 기준이 명확한가?
- 핵심 여정이 불필요한 단계·입력을 줄이고 중단·취소·재시도·복구 경로를 포함하는가?
- 정보 구조, 행동 우선순위와 UX 문구가 사용자가 다음 행동을 예측할 수 있게 하는가?
- `semantic token | light | dark | 용도·상태` 컬러 표가 있고 두 모드의 토큰이 1:1로 대응하는가?
- 두 모드에서 텍스트·아이콘·경계·상태 색의 대비와 구분이 확인됐는가?
- 역할별 font family·fallback·크기·굵기·line-height가 정리되고 사용자 승인을 받았는가?
- 필요한 spacing, radius, shadow, icon과 motion 원칙이 정리됐는가?
- 로딩·빈 상태·오류 상태가 정의됐는가?
- 키보드, 포커스와 접근성 요구가 포함됐는가?
- 모바일·데스크톱 우선순위가 설명됐는가?
- 기존 DEVUP UI 컴포넌트와 `devup.json` 토큰을 재사용하는가?
- 사용자가 선택된 방향의 Design Foundation을 승인했는가?

### 3. Scope Expansion Gate

비교와 foundation 승인 단계의 작업 범위는 대표 페이지 하나로 제한한다. 방향 선택과 foundation 승인이 모두 끝난 뒤 선택된 대표 페이지를 확정할 수 있다. 나머지 페이지는 사용자가 후속 작업을 명시한 다음 별도 범위로 계획하며 자동으로 확장하지 않는다.

## Implementation Gate

- 구현 대상이 승인된 대표 페이지 또는 사용자가 별도로 요청한 후속 페이지 범위 안에 있는가?
- 페이지, 공용 UI, 기능 코드, service와 utility의 기존 폴더 책임을 유지하는가?
- 신규 스타일이 CSS-in-JS 원칙과 일반 CSS 예외 범위를 따르는가?
- 승인된 semantic color와 typography token만 사용하며 라이트·다크 모드에 임의의 미대응 토큰이나 raw color를 추가하지 않았는가?
- 상태 객체와 배열을 직접 변경하지 않는가?
- 비동기 행동에 진행·성공·실패 피드백이 있고 중복 실행을 방지하는가?
- 오류가 발생해도 사용자 입력을 가능한 한 보존하고 명확한 복구 경로를 제공하는가?
- 파괴적이거나 되돌리기 어려운 행동은 확인·취소 또는 되돌리기 수단을 제공하는가?
- 오류·빈 상태와 접근성 요구를 구현했으며 다크 패턴이 없는가?

## Verification Gate

개발 중에는 영향 범위에 맞춰 `pnpm lint`, `pnpm test`, `pnpm typecheck`, `pnpm build`를 선택한다. UI·사용자 흐름 변경은 [UI 수동 점검표](ui-smoke-checklist.md)의 `scoped` 또는 `full` 수준을 추가한다.

PR 생성·업로드 또는 최종 반영 전에는 프로젝트 `AGENTS.md`의 전체 PR Gate와 UI 변경 범위에 맞는 수동 점검을 수행한다.
